# TDD-Enforced Sprint Plan for Cogdoc Completion

## How TDD is enforced here

A **sprint gate** blocks advance to the next sprint. The gate is mechanical, not opinion-based:

> **Gate = all unit + integration tests green AND ≥80% line+branch coverage on `src/lib/` + `src/app/api/` (TS) and the FastAPI service (Python, once it exists).** `bun run test` and `pytest` must both exit 0 with coverage above floor.

Two distinct TDD regimes, matched to the work type:

| Work type | Regime | Why |
|---|---|---|
| **Net-new features** (friction modes, Devil's Autocomplete, Blindspot Monitor, evaluation harness) | **Strict Red→Green→Refactor**: write failing test first, implement to green, then refactor | Standard TDD on new code |
| **Migrations** (contentEditable→Tiptap, keyword→pgvector, Next.js→FastAPI, blocking→SSE) | **Characterization-first**: write tests that capture *current* behavior → go green on old code → refactor/swap behind a feature flag → tests stay green throughout | TDD on a rebuild without characterization tests is guesswork (Feathers, *Working Effectively with Legacy Code*) |

This distinction is the load-bearing decision. Without it, "TDD during migration" produces either no tests or tests that describe the aspirational system instead of the real one.

## Gate enforcement mechanics

- **Branch per sprint:** `sprint-0`, `sprint-1`, … A sprint merges to `main` only after `scripts/gate.sh` exits 0. `main` is always demoable.
- **Coverage floor is non-negotiable** — if coverage is 79.9%, the gate fails. This is what "enforce" means in practice.
- **Multi-agent rule:** one file = one owner at a time; the `ai-gateway.ts` seam is the only shared merge point and is queued, never concurrently edited.
- **Characterization tests are immutable within a sprint** — if a migration needs to change a characterization test, that's a contract change requiring a `CONTRACTS.md` update first.
- If a sprint cannot pass its gate in its window, the documented **cut order** is: experimental engines (Sprint 3) → SSE (Stream D) → Tiptap (Stream C). **Never cut:** pgvector + evaluation (Sprint 1) and friction calibration — those are the grade and the research.
